Product Requirements Document (PRD)

Sistem Penerimaan Tamu Sekolah

1. Ringkasan Proyek

Aplikasi berbasis web untuk mendigitalisasi proses pencatatan dan penerimaan tamu di lingkungan sekolah. Sistem ini akan mencatat identitas, mengambil foto wajah tamu, mengumpulkan data kunjungan, dan mencetak kartu akses pengunjung secara instan.

2. Tujuan Utama

  • Meningkatkan keamanan sekolah dengan memverifikasi setiap tamu yang masuk.
  • Mempercepat proses registrasi di meja resepsionis atau pos satpam.
  • Menyediakan pangkalan data historis kunjungan yang rapi dan mudah dilacak.

3. Alur Pengguna (User Flow)

  1. Akses Awal: Pengguna membuka situs dan dihadapkan pada halaman Login.
  2. Autentikasi: Pengguna masuk menggunakan kredensial yang sah.
  3. Verifikasi Visual: Sistem meminta izin akses kamera dan mengambil foto wajah tamu.
  4. Pengisian Data: Tamu atau staf melengkapi formulir detail kunjungan.
  5. Konfirmasi & Cetak: Sistem menampilkan ringkasan data dan foto, dilengkapi tombol untuk mencetak Kartu Pengunjung.

4. Spesifikasi Fitur Utama

A. Halaman Akses (Login Page)

Fitur: Form input Username/Email, Password, dan tombol Submit.
Fungsi: Autentikasi awal untuk membatasi akses aplikasi hanya bagi staf yang berwenang.

B. Halaman Pengambilan Foto (Face Capture Page)

Fitur: Integrasi API Kamera (Webcam), antarmuka viewfinder, tombol ambil foto, dan retake.
Fungsi: Menangkap wajah tamu secara real-time untuk dicetak pada kartu ID pengunjung.

C. Halaman Formulir Registrasi (Guest Form)

  • Nama Lengkap & Instansi: Input teks.
  • Tujuan Kunjungan: Dropdown (contoh: Rapat, Bertemu Siswa/Guru, Pengiriman Barang).
  • Jadwal & Waktu: Komponen Date & Time picker otomatis.
  • Pihak yang Dituju & Kontak: Input teks dan numerik dengan validasi.

D. Halaman Konfirmasi & Cetak

Fitur: Pratinjau (Preview) ID Card pengunjung.
Fungsi: Menggunakan fungsi cetak pada peramban web untuk mencetak ID tamu langsung ke printer yang terhubung.

5. Spesifikasi Teknis & UI/UX

Pengembangan antarmuka akan difokuskan pada desain yang bersih (clean design) dan responsif. Implementasi UI akan menggunakan Tailwind CSS yang dipadukan dengan komponen dari Shadcn UI. Pilihan teknologi ini akan sangat mempercepat proses *vibe coding* dalam menyusun struktur komponen frontend.

6. Pedoman Audit Keamanan & Bug (Security Review)

Karena alur pengembangan menggunakan metodologi hybrid vibe coding, setelah kode di-generate, audit manual difokuskan untuk mencari celah pada titik-titik krusial berikut:

  • Bypass Autentikasi (Broken Access Control): Memastikan halaman form dan cetak tidak dapat diakses paksa melalui URL tanpa melewati halaman login.
  • Izin Perangkat (Camera Permissions): Menyediakan skenario fallback yang aman tanpa menyebabkan aplikasi crash apabila akses kamera ditolak oleh browser tamu.
  • Validasi Input (XSS & SQL Injection): Melakukan sanitasi ketat pada input teks (nama, instansi) agar terhindar dari eksekusi *script* berbahaya.
  • Keamanan File Upload: Memastikan pengambilan gambar hanya menyimpan format yang aman (.jpg/.png) ke dalam storage.
